# Phase 4 レポート(Discord 連携)

- 実施日: 2026-10-10 / 実機: Windows 11(Mac 実機なし)
- 判断: [decisions.md](decisions.md)

## 実装したもの
- **スラッシュコマンド**: `/sessions`(一覧、プロファイルと状態つき)、`/send session text`(指示の送信)、`/status session`(直近の画面)、`/stop session`(Esc)、`/usage`(全プロファイルの使用量)、`/new profile project prompt`(新規セッション)。セッション名などは入力補完が出る
- **セッション = スレッド**: セッションごとにスレッドを作り、承認待ち・完了・エラー・上限到達と、作業中の進捗(既定 60 秒ごと、変化があったときだけ)を投稿する。画面はエスケープを除いたテキストで、長い場合はファイル添付
- **承認ボタン**: 承認待ちになると「許可 / 拒否 / 詳細を見る」を投稿する。押すとセッションに応答を送る。待ちが続くと再通知(既定 5 分ごと、最大 3 回)
- **完了通知**: 長い作業(既定 60 秒以上)の完了時にメンションし、変更ファイル数と追加/削除行数を添える
- **使用量の通知**(Phase 3)もチャンネルへ送る
- **セキュリティ**:
  - 許可リスト外のユーザーは無視してログに記録
  - 操作の範囲は設定で制限(既定: 送信と承認のみ)
  - 危険な操作は Discord 上で追加確認
  - 秘密情報らしき文字列は伏せて送信
  - トークンは OS のキーチェーンで暗号化
  - Discord からの操作はアプリにも表示
- **設定画面**: ⚙ 設定 →「Discord 連携の設定…」(コマンドパレットからも開ける)。準備の手順、トークン、サーバー / チャンネル / 許可ユーザーの ID、許可する操作、メンション、再通知、スリープ防止

## 完了条件の確認
> スマホのDiscordから、指示送信と承認ができる。許可リスト外のユーザーは無視される。

| 項目 | 自動テスト(Windows) | 実際の Discord |
|---|---|---|
| `/send` で、実際のセッション(偽の claude)に指示が入力される。アプリに「Discord から」が出る | ✅ 結合テスト(本物のセッション管理 + PTY + フック、Discord の部分だけ偽物) | ⏳ 利用者の Bot が必要 |
| 承認待ちで「許可 / 拒否 / 詳細」が投稿され、「許可」で応答が送られて作業中に戻る | ✅ 結合テスト | ⏳ |
| 許可リスト外のユーザーのコマンドとボタンは無視され、ログに残る | ✅ 結合テスト(回帰テスト) | ⏳ |
| 危険な指示(git push --force)は確認が必要で、別のユーザーは確認できない | ✅ 結合テスト | ⏳ |
| 画面の API キーは伏せて送る | ✅ 結合テスト | ⏳ |
| /new・/stop は既定で無効、有効にすると /new で開始して最初の指示を送れる | ✅ 結合テスト | ⏳ |
| トークンは暗号化して保存し、設定・DB・ログのどこにも平文で残らない。画面にも返さない | ✅ E2E(開発版・パッケージ版) | — |
| Mac | ⏳ CI(未実行) | ⏳ |

**結論:** 完了条件は、Discord の部分を偽物に置き換えた自動テストで満たしている。実際のスマホの Discord からの確認は、利用者が Bot を用意したあとに行う。

## 実際の Discord で確認する手順(利用者)
1. `npm run dev` → ⚙ 設定 →「Discord 連携の設定…」を開き、画面の「準備」の 1〜4 を行う
2. トークンを入力して「保存して接続」→ 状態が「接続済み: ボット名」になる
3. スマホの Discord で `/sessions` → 一覧が出る。`/send` で指示を送る → PC の CodeDeck に「📱 Discord から」と出て、claude が動く
4. claude がツールの許可を求めたとき(Auto mode でない場合)にスレッドへボタンが出る →「許可」で進む
5. 別のアカウント(許可リストにないユーザー)で `/send` → 何も起きない(userData/logs/codedeck.log に記録される)
