## 現在 CI で確認していること(両 OS)
`npm ci` → lint → Prettier → 型チェック → ユニットテスト(110 件)→ ビルド → E2E(開発版)→ 署名なしのパッケージ化 → E2E(パッケージ版)

E2E は、偽の claude(本物と同じく `--settings` のフックを実行する)を使い、次を確かめている:

- 2つのプロファイルの同時実行と、再起動後の復元(Phase 1)
- 状態の表示、ペイン、パレット、テーマ、メモ、別ウィンドウ(Phase 2)
- 使用量のしきい値通知が1回だけ出ること、上限到達の検出(Phase 3)
- Discord トークンの暗号化保存(Phase 4)

**Mac は実機がないため、CI で確認できた範囲が Mac の確認結果になる。**

## CI で見つかった問題(すべて修正済み)

| 問題 | 影響 | 直し方 |
|---|---|---|
| macOS で、すべてのターミナルの起動が `posix_spawnp failed` で失敗 | **Mac 版ではセッションが1つも動かない重大な不具合**だった | npm でインストールすると、node-pty の `spawn-helper` に実行権限が付かない。`postinstall`(`scripts/fix-node-pty.mjs`)で付け、起動時にも確認する |
| Windows で、セッションを閉じるとアプリが固まることがある(終了できない) | 古い Windows(Server 2022/2025、Windows 10 など)で発生しうる | node-pty が Windows 標準の ConPTY を閉じるとき、出力の読み取りを止めてから閉じ、閉じる処理が出力を待ち続ける。node-pty 同梱の ConPTY(Windows Terminal と同じもの)を使うように変更(`useConptyDll`) |
| macOS で、終了時に別ウィンドウが先に閉じると、再起動後に復元されない | ⌘Q で終了すると別ウィンドウが失われる | 終了処理の開始時点(`before-quit`)で「終了中」とし、その後に閉じたウィンドウは一覧から外さない |
| Windows で、テストのプロセスが異常終了する(0xC0000409) | テストのみ | 一時フォルダをテストのプロセス内の `fs.rmSync` で消すと、新しい Node の Windows 版では、使用中のファイルがあるとプロセスごと落ちることがある。別のプロセスで削除する。アプリ本体の1ファイルの削除も `unlinkSync` にした |
| E2E の再試行で、前回の状態が残る | テストのみ | テストごと(再試行ごと)に新しい一時フォルダを使う |
| 狭いウィンドウで入力が折り返され、表示の一部が欠ける。別ウィンドウへの入力が早すぎる | テストのみ | 折り返しに依存しない確認方法にし、入力先が移ってから打つ |

## 運用
- 失敗したテストは、実行結果のページに注釈として表示される(ログをダウンロードせずに読める)。失敗したテストでは、アプリの出力の最後の 60 行を表示する
- CI に限り、失敗したテストを1回だけ自動で再試行する
