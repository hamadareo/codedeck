# Phase 6 実装計画(仕上げ)

利用者の指示(2026-10-10「進めてください。完璧な状態になったら Mac 版も作成してください」)を承認として扱う。

## 1. スケジュール実行(§5)
- 時刻を指定してプロンプトを自動で実行する: 「毎日 HH:MM」「平日 HH:MM」「毎週 曜日 HH:MM」「一度だけ 日時」
- プロファイル(必須)、プロジェクト(任意、なければホーム)、指示、有効 / 無効。実行するとそのプロファイルの新しいセッションを開き、claude が入力待ちになってから指示を送る。実行したら通知する
- **常駐が必要な旨を明示**: 「CodeDeck が起動している間だけ実行されます」を画面に表示。設定に「ウィンドウを閉じてもトレイに常駐する」「ログイン時に起動する」を追加(どちらも既定オフ)。スケジュールが有効なのに常駐がオフなら案内を出す
- 起動していなかった間に時刻を過ぎた予定は、起動時に1回だけ「実行しなかった」と通知する(勝手にまとめて実行しない)

## 2. SSH セッション(§5)
- 接続先(名前、`user@host`、ポート、鍵ファイル(任意)、リモートの作業フォルダ、リモートの `CLAUDE_CONFIG_DIR`(任意))を保存する。パスワードや鍵の中身は保存しない
- OS の `ssh` コマンド(macOS 標準、Windows 10 以降の OpenSSH)を PTY で起動し、`cd <フォルダ> && claude --session-id …` をリモートで実行する。パスワードの入力や鍵の確認はターミナルで利用者が行う
- リモートのセッションも再起動後に `--resume` で再開する。状態の検出(フック)はリモートでは使えないため「実行中」表示になる旨を画面に出す

## 3. パフォーマンス(§4: 10 セッション同時で入力遅延を体感させない)
- PTY の出力を main でセッションごとにまとめ(最大 8ms)、IPC の回数を減らす
- xterm の WebGL 描画を使う(使えない環境では従来の描画)
- 表示していないセッションは描画しない(既存)
- E2E で、10 セッションが大量に出力している最中のキー入力の反映時間を計測する

## 4. 配布物(§2.5)
- アイコンを用意(PNG から electron-builder が .icns / .ico を生成)
- macOS: `.dmg`(universal: Apple シリコンと Intel)。署名と公証は、CI に Apple の証明書・アカウントの Secrets がある場合だけ行う(ない場合は署名なしで作り、開き方を README に書く)。node-pty 用の entitlements
- Windows: NSIS の `.exe` インストーラー(インストール先を選べる)
- **自動更新**: electron-updater(GitHub Releases)。起動時と 6 時間ごとに確認し、ダウンロード後に「再起動して更新」を表示。設定でオフにできる。開発版では動かない
- **リリースの自動化**: `v*` のタグを push すると、GitHub Actions が Mac と Windows でビルドし、GitHub Release(下書き)に添付する

## 完了条件の確認方法
> クリーンな Mac とクリーンな Windows の両方で、インストーラーからインストールし、主要フロー(プロファイル追加→セッション起動→Discord 操作→使用量通知)が動く。

- Windows: 作ったインストーラーを、ローカルの別フォルダにサイレントインストールし、インストールされたアプリに対して E2E を実行する(CI でも同様)
- Mac: 実機がないため、CI(クリーンな macOS ランナー)で dmg を作り、dmg からアプリを取り出して E2E を実行する
- Discord 操作は、実際の Bot(利用者の設定待ち)以外は結合テストで確認済み
