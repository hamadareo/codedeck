# Phase 3 レポート(使用量と通知)

- 実施日: 2026-10-10 / 実機: Windows 11(Mac 実機なし)
- 計画: [phase3-plan.md](phase3-plan.md)、判断: [decisions.md](decisions.md)

## 実装したもの
- **使用量の推定**: プロファイルごとに、会話の記録(JSONL)からトークン数と時刻だけを読み、5時間ウィンドウと7日ウィンドウの消費を計算する。追記された分だけを読み、1分ごと + セッションの作業が終わるたびに再計算する
- **上限値**: プランを `claude auth status` から自動判定し、仮の目安を表示する。プロファイルごとに、プランの選択、5時間 / 7日の上限、通知するしきい値を変更できる。上限到達のメッセージを検出すると、その時点の値を「実測の上限」として保存する
- **上限到達の検出**: ターミナルの「limit reached」などのメッセージを検出し、セッションの状態を「上限到達」(⏸)にして、リセット時刻をサイドバーに表示する
- **通知**: しきい値(既定 70 / 90 / 100%)の超過、上限到達、「再び使えます」(リセット)、セッションの完了 / 承認待ち / エラー。OS 通知(Windows トースト / macOS 通知センター)とアプリ内バナー。設定画面で種類ごとに ON/OFF。OS 通知をクリックすると、そのセッションを表示する
- **表示**: サイドバーのプロファイルごとに使用量バー(5時間 / 7日、% とリセットまでの時間)。右パネルの「使用量」タブに詳細、設定、通知の履歴。トレイ(メニューバー)のアイコンの色とメニューに、プロファイルごとの使用量
- Discord への通知は Phase 4 で追加する

## 完了条件の確認
> しきい値を超えたときに、1回だけ通知が出る。テストデータで検証できる。

| 項目 | Windows | Mac |
|---|---|---|
| テスト用の会話の記録で 75% → 70% の通知が1回だけ出る。再計算を繰り返しても、再起動しても、もう一度は出ない | ✅ E2E(開発版・パッケージ版とも2回ずつ成功) | ⏳ CI(未実行) |
| さらに使って 95% → 90% の通知が1回だけ出る(70% は再び出ない) | ✅ E2E | ⏳ CI |
| 一度に複数のしきい値を超えたら、いちばん高いものだけ。新しい5時間ウィンドウで再び通知される。リセットの通知は1回 | ✅ ユニットテスト(再起動をまたぐ回帰テストを含む) | 同左 |
| ターミナルの上限到達メッセージ → 状態が「上限到達」、通知が1回、リセット時刻の表示 | ✅ E2E(偽の claude が本物と同じ形式のメッセージを出す) | ⏳ CI |
| OS 通知(トースト)が実際に表示される | ⏳ 手で確認が必要(E2E では表示せずに記録だけ確認) | ⏳ |
| 本物の記録での推定値の妥当性 | ⏳ 実際に使いながら確認が必要(目安は非公式) | ⏳ |

**結論:** 完了条件「しきい値を超えたときに1回だけ通知が出る。テストデータで検証できる」は、Windows で満たした。Mac は CI での確認待ち。

## テスト
- ユニット(Vitest): 94件(+1件は Mac/Linux 用で Windows ではスキップ)。追加: 使用量の計算(ブロック、移動窓、%、リセット時刻)、記録の読み取り(追記分だけ、書きかけの行、重複の除外、本文を保持しないこと)、しきい値(飛び越し、重複なし、再起動をまたいでも重複なし、新しいウィンドウでの再通知)、リセット通知、上限メッセージの検出と実測値での調整(手動の値は上書きしない)、通知の振り分け(前面にあるときのセッション通知、種類ごとの OFF)
- E2E: `phase3.spec.ts` を追加し、CI のパッケージ版のテストにも加えた

## 手で確認してほしいこと(`npm run dev`)
1. サイドバーの「個人」に使用量バーが出る(プランは Pro と自動判定され、「仮の目安(非公式)」と表示される)
2. 右パネル(▥)→「使用量」で、上限やしきい値を変更できる
3. CodeDeck を最小化して claude に作業させる → 完了時に Windows のトースト通知が出て、クリックするとそのセッションが開く
4. タスクバー右下(トレイ)の CodeDeck のアイコンにマウスを合わせる / 右クリックすると、使用量が表示される
